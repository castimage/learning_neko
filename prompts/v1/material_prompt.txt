## RULES
- 学习资料正文必须用 Markdown 书写，至少包含定义、机制解释、一个具体例子三个层次。
- 正文严格限定在本分节的学习目标范围内，不得提前展开后续分节的内容，也不得引入资料正文之外的知识。
- 例题必须能仅凭本分节正文作答，不依赖后续分节。
- 例题的 knowledge_point 必须取自本节的 section_keywords（即 {{ section_keywords }}），不得引入其他分节的概念；如果某道题想考的概念不在这个集合里，说明它已经越出本节范围，应当删掉这道题。
- 例题以选择题或填空题为主，每题必须给出正确答案与解析；解析要说明错误选项错在哪里。
- 选择题至少要给出三个选项，且只有一个正确，干扰项要似是而非；如果某个考点只有一个合理的迷惑点，就改成填空题（options 返回空数组），不要为了凑选项而编造牵强的干扰项。
- 知识点关系图必须面向本分节，节点数量控制在四到十个。
- 关系图中每条边的起点与终点都必须是图中已声明的节点编号，不得引用不存在的节点。
- 边的方向约定统一为「从更根本、更靠前的概念，指向更派生、更靠后的概念」，不要反过来连。按下表选择 kind，并为每条边挑最贴切的那一个：
  - hierarchy：source 是更一般的概念，target 是它的一种具体情形或下位概念。例：学习率 → 学习率过大。
  - contains：source 是整体，target 是它的组成部分。例：参数更新公式 → 学习率 η。
  - prerequisite：source 是前提条件，target 是依赖它才能成立的结论。例：负梯度方向 → 参数更新。
  - causes：source 是起因，target 是它导致的后果。例：步长过大 → 损失在最优点附近震荡。
  - contrast：两者并列对比，方向不重要。例：学习率过大 ↔ 学习率过小。
  - related：一般相关但说不清上述任何一种，方向不重要。
- 每种关系优先用最具体的那个 kind，不要一律用 hierarchy 兜底；如果两个概念之间确实同时符合多种关系，选信息量最大的那一种。
- 每个节点的 label 必须是资料正文中出现过的概念名词；detail 要解释这个节点自己的概念，不要拿 detail 去解释另一个相关概念。
- 需要配图时先分清两类来源：能由坐标轴与曲线表达清楚的示意图（diagram）、以及随时间变化的动画（animation），这两类由你直接给出绘制规格；除此之外的真实图片、音频与视频（image/audio/video）只能引用 available_assets 中列出的 key，你无法产出这类素材本身。
- 引用素材时 asset_key 必须逐字取自 available_assets；diagram 与 animation 的 asset_key 一律留空（空字符串或 null 皆可，不要编造 key），并且不要同时给出另一种规格。
- 素材要出现在正文里的确切位置，就在该处写一个占位符：![图注](media:<id>)，其中 <id> 必须是 media 列表里声明过的 id，**或等于 visualization.id**；占位符不要集中堆在文末。
- media 里只放正文真正用到的素材；用不上的素材直接不要写进 media，不要为了凑数量而在正文里补占位符。
- 知识点关系图只用 visualization 表达，不要再用一份 diagram 去重复画同一张图。
- 知识点关系图也应当出现在正文里的确切位置：先在 visualization.id 里给它一个编号，再在正文讲完相关概念的那一段之后写 ![关系图](media:<visualization.id>)，且两处编号必须逐字一致。这样关系图会嵌在讲解旁边，而不是只能堆在文末。

输出为 JSON 对象，字段含义与取值要求如下：
- material：字符串，学习资料的 Markdown 正文。
- examples：对象数组，每个元素含 q_id（题目编号，形如 ex-1）、question（题干）、options（选项字符串数组，填空题则返回空数组）、answer（正确答案）、analysis（解析，需点明易错处）、knowledge_point（该题对应的知识点，必须取自本节 section_keywords）、difficulty（取值只能是「基础」或「进阶」）。
- visualization：对象，描述知识点关系图，含：
  - id：字符串，这张关系图的编号，供正文占位符 ![关系图](media:<id>) 引用；不要与 media 里的 id 重复。
  - title：字符串，图的标题。
  - direction：字符串，取值只能是 "top_down"、"left_right"、"radial" 之一。
  - nodes：对象数组，每个元素含 id（节点编号，图中唯一）、label（节点显示文本，不超过十五字）、kind（取值只能是 "root"、"concept"、"detail"、"example"、"warning" 之一）、detail（该节点的补充说明）。
  - edges：对象数组，每个元素含 source（起点节点 id）、target（终点节点 id）、kind（取值只能是 "hierarchy"、"contains"、"prerequisite"、"causes"、"contrast"、"related" 之一）、label（边的标签，可为空字符串）。
  - groups：对象数组，每个元素含 id（分组编号，图中唯一）、label（该分组的显示名称）、node_ids（该组包含的节点 id 数组，编号必须来自 nodes）；用于把相关节点归为一类，可为空数组。
  - notes：字符串数组，图中需要额外提示的注意事项，可为空数组。
- media：对象数组，本分节的配图、动画与素材引用，可为空数组。每个元素含：
  - id：字符串，素材编号，在同一份产物内唯一，供正文占位符引用。
  - kind：字符串，取值只能是 "diagram"、"animation"、"image"、"audio"、"video" 之一。
  - caption：字符串，该素材的图注；引用类素材必填。
  - alt：字符串，替代文本，供无法渲染时兜底。
  - asset_key：字符串；kind 为 image/audio/video 时必填且必须逐字取自 available_assets，kind 为 diagram/animation 时留空（空字符串或 null）。
  - diagram：对象或 null；仅当 kind 为 "diagram" 时给出，含：
    - title：字符串，图的标题。
    - axis：对象，含 x_label、y_label（坐标轴名称）与 x_min、x_max、y_min、y_max（四个数值，必须满足 x_min < x_max 且 y_min < y_max）。
    - series：对象数组，每个元素含 id（曲线编号，图内唯一）、label（曲线名）、style（取值只能是 "solid"、"dashed"、"dotted" 之一）、points（对象数组，每个元素含 x 与 y 两个数值，至少两个点）。
    - marks：对象数组，每个元素含 text（标注文字）、x、y（标注落点坐标），可为空数组。
  - animation：对象或 null；仅当 kind 为 "animation" 时给出，含：
    - title：字符串，动画的标题。
    - axis：对象，结构同 diagram.axis。
    - tracks：对象数组，每个元素含 id（曲线编号，动画内唯一）、label（曲线名）。
    - frames：对象数组，至少两帧，按 t 严格递增排列；每个元素含 t（该帧在时间轴上的位置）与 samples（对象数组，每个元素含 track_id 与 value 两个字段；每条 track 在每一帧都必须有一个 sample）。
    - playback：对象，含 duration_ms（正整数）、fps（1 到 60 的整数）、loop（布尔）、autoplay（布尔）。
    - marks：对象数组，结构同 diagram.marks，可为空数组。
